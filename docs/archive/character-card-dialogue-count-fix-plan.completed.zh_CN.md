# 角色卡目标对话组数修复计划

> 归档状态：计划已于 2026-09-04 完成并通过自审查。PR 链接在远端创建后回填。

## 完成记录

- 已把用户可见语义统一为“目标对话组数”，同时保留旧 JSON 字段名以兼容已有角色卡。
- 首次编译结果不足时，会通过统一模型中间件发起一次证据约束的缺口补充请求；已有和新增对话按规范化内容去重，仍不足时明确使编译失败。
- 新增 5 项核心回归测试；与 AstrBot 导出测试合计 12 项通过，统一离线回归 180 项通过，四语 i18n、Ruff 和 Markdown 链接校验通过。
- 第一轮自审查发现新增 Prompt purpose 缺少四语显示名称，修复后从完整验证和整体审查重新开始；第二轮未发现本次范围内的剩余问题。
- 审查同时发现提示词页面另有 10 个既有 Prompt purpose 缺少四语名称；它们早于本计划且不影响本次新增 purpose，未扩大范围处理。

## 1. 范围

修复角色卡页面的对话数量设置，使显式填写的数量成为可验证的最终目标，而不是仅依赖模型遵循的软提示。覆盖设置文案、编译请求、结果补齐、错误反馈、测试和文档。

## 2. 非目标

- 不修改角色卡 JSON 中既有 `user_metadata.extra_dialogue_count` 字段名，避免破坏旧卡兼容性。
- 不伪造或机械复制重复对话来凑数。
- 不改变留空时由模型自动决定数量的行为。
- 不绕过 `utils.ai_model_middleware`，不新增依赖。
- 不修改知识库结构、证据分层或外部角色卡格式。

## 3. 已确认决策

- 用户可见名称改为“目标对话组数”，明确它表示最终总数，不是追加数量。
- 留空表示自动；`0` 表示最终不保留对话组；正数表示编译成功时必须得到恰好该数量。
- 首次角色卡编译仍要求模型直接生成目标数量。
- 首次结果不足时，使用同一模型预设发起一次专门的补充生成请求，只请求缺少数量，并携带正式知识库摘要、分层证据和已有对话，避免重复和无证据扩写。
- 补充结果与已有结果按规范化内容去重，再截断到目标数量。
- 一次补充后仍不足时，编译明确失败并报告期望值与实际值，不再以成功状态静默保存数量不足的卡。
- 对话补充请求通过新的默认 prompt purpose 进入统一模型中间件，并在提示词页面暴露变量说明。

## 4. 当前状态与目标状态

当前实现能正确保存设置并把数量说明放入编译 Prompt；`0` 能强制清空，过多结果能截断。但正数不足时，本地逻辑只能在 `preset_dialogues` 与 `example_dialogues` 间搬运已有条目，最终只写 warning，因此模型少返回时设置看起来不生效。UI 的“额外对话组数”又与代码的最终总数语义不一致。

目标状态是：编译成功即代表相关对话集合恰好符合显式目标；无法补齐时给出明确失败，不生成重复样例，不掩盖数量偏差。

## 5. 模块边界

- `core/character_card_compiler.py`：计算缺口、构建补充请求、解析与去重、执行最终数量断言。
- `res/default_prompts.json`：保存补充生成的 system/user prompt，不在 core 硬编码正文。
- `gui/widgets/character_card_detail_panel.py`：继续只负责编辑和保存数值。
- `gui/pages/character_card_page.py` 与 worker：沿用现有编译线程，不直接补生成。
- `i18n/`：同步四语字段名、占位提示、编译阶段和错误语义。

## 6. 里程碑

### M01：严格数量规则与纯函数

交付：

- 将现有后处理拆成对话池选择、有效组过滤、去重、镜像和最终数量检查。
- 保持留空、零、截断行为；正数不足返回明确缺口。

验收：

- `0` 得到空列表；超过目标会稳定截断。
- 两套对话可合并且不会重复。
- 不完整或空消息组不计入有效数量。

### M02：证据约束的补充生成

交付：

- 新增角色卡对话补充 prompt purpose。
- 首轮不足时发起一次缺口请求，并将返回组与已有组去重合并。
- 补充后仍不足时使编译失败，错误包含期望数量和实际数量。

验收：

- 已满足目标时不增加模型调用。
- 缺少 N 组时，请求变量中的数量就是 N。
- 重复补充结果不会被计数。
- 不足不会再以编译成功结束。

### M03：UI、文档与回归

交付：

- 四语 UI 将“额外”改为“目标”，说明留空、零和正数语义。
- 提示词变量帮助、架构说明和稳定工作流文档同步。
- 增加 core 回归测试，覆盖不同编译目标和失败路径。

## 7. 验证与自审查

依次执行：

1. `uv run --locked python -m unittest` 运行新增的角色卡编译数量测试。
2. `uv run --locked python scripts/validate_i18n_keys.py`
3. `uv run --locked ruff check .`
4. `uv run --locked python scripts/validate_multi_material_regression.py`

整体自审查检查：

- UI、持久化、Prompt 和最终断言是否采用同一“最终目标数量”语义。
- 补充请求是否只在不足时发生，且仍通过统一模型中间件。
- 是否可能产生重复、空组、无限重试或不可控调用次数。
- 三种编译目标的主对话集合是否正确。
- 错误、阶段文案、四语 i18n、Prompt 帮助和文档是否完整。
- 用户数据、原子保存和已有空值/零值兼容是否保持。

发现问题后修复，并从全部验证和整体自审查重新开始；只有最终无问题且 CI 通过才合并 PR。
